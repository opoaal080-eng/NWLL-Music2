NIGHTWELL MUSIC — ПАКЕТ СЕРВЕРНЫХ ОБНОВЛЕНИЙ
Версия исходников: определяется коммитом GitHub Actions, см. provenance.txt.

Это ДОПОЛНЕНИЕ к существующему Windows-серверу Nightwell Music.
В репозитории нет полной текущей серверной папки с работающим app.py,
поэтому это не новый сервер "с нуля" и не замена рабочей базе данных.

================= БЫСТРАЯ УСТАНОВКА =================

1. Сделай отдельную копию папки и базы текущего сервера.
2. Распакуй этот ZIP в отдельную папку, НЕ поверх работающего сервера.
3. Запусти Check_Nightwell_Server.bat.
   По умолчанию проверяется C:\Nightwell Music\nightwell-music
   Если папка другая, передай её первым аргументом bat.
4. Если проверка показала совместимость, останови действующий сервер.
5. Запусти Install_Nightwell_Server.bat.
6. Перезапусти сервер своим СУЩЕСТВУЮЩИМ батником.
   Не нужно запускать Docker или второй экземпляр сервера.

Установщик:
- Проверяет наличие app.py, верхнеуровневых app и identity(request),
  а также маршрута /api/tracks.
- Перед изменениями сохраняет оригиналы файлов в backups\nightwell-server-update-...
- Добавляет серверные маршруты только если они ещё не зарегистрированы.
- Копирует обновлённые Python-модули, не трогая пароли, сертификаты, Caddyfile,
  порт 80/443, пользовательские библиотеки и существующие базы.
- Отказывается менять неизвестную структуру app.py и конфликтующие маршруты.
- Не устанавливает Python-пакеты автоматически.
- Не включит Gmail/SMTP/Lava и не выдаёт премиум без проверки оплаты.

Для отката используй Rollback_Nightwell_Server.bat с папкой резервной копии.
Установщик отката откажет, если файлы изменялись ПОСЛЕ установки, чтобы не
стереть дальнейшие изменения. Базы, созданные модулями, при откате не удаляются.

================= ЧТО ВКЛЮЧЕНО =================

1. КАТАЛОГ ИСПОЛНИТЕЛЕЙ [АВТОУСТАНОВКА, СОВМЕСТИМЫЙ APP.PY]
   Файлы: artist_catalog.py, artist_metadata.py
   GET /api/artists?q=...
   GET /api/artists/profile?name=...
   Ищет исполнителей и отдаёт их треки по существующему /api/tracks.
   Отличает аккаунт загрузчика аудио от музыканта по явным кредитам или
   виду "Исполнитель — Название". Исполнители без подтверждённого
   имени не индексируются. Старые ошибочные связи удаляются при обновлении
   индекса соответствующего трека.
   Отдельные фото работают только с собственным HTTPS CDN и JSON-сопоставлением.
   Для этого укажи NW_ARTIST_IMAGE_MAP и NW_ARTIST_IMAGE_HOSTS (см.
   server-updates\artist-catalog\README-RU.md).
   В каталоге показываются ТОЛЬКО обнаруженные в доступных треках артисты.

2. ЕЖЕДНЕВНЫЕ ПОДБОРКИ [АВТОУСТАНОВКА, СОВМЕСТИМЫЙ APP.PY]
   Файл: daily_public_playlists.py
   GET /api/daily-public-playlists
   Три стабильные подборки на аккаунт и день с SQLite-кэшем.
   Пока псевдослучайные, без персонализации по истории прослушиваний.

3. УЛУЧШЕННЫЙ ПЕРЕНОС ПЛЕЙЛИСТОВ [КОПИРУЕТ ФАЙЛЫ]
   Файлы: music_import.py и music_import_sources.py
   Более гибкий поиск, транслитерация, обработка CSV/JSON/TXT, дедупликация.
   Самостоятельно серверные маршруты не создаёт. Если действующий app.py
   уже интегрирован с music_import.py, обновлённый код начнёт использоваться
   после перезапуска. Если интеграции нет, нужна ручная адаптация.

4. РЕГИСТРАЦИЯ И ВХОД ЧЕРЕЗ EMAIL [ОТДЕЛЬНЫЙ МОДУЛЬ, НЕ АВТОВКЛЮЧЁН]
   Каталог: server-updates\email-auth\
   Имеется отдельный установщик install_email_auth.py.
   Требуются совместимый app.py и настройка SMTP через mail_setup.py.
   Без этого письма и коды подтверждения работать не будут.
   Не меняй настройки действующих аккаунтов без резервной копии.

5. LAVA.TOP WEBHOOK [ОТДЕЛЬНЫЙ МОДУЛЬ, НЕ АВТОВКЛЮЧЁН]
   Файлы: server\lava_webhook.py и server\README-LAVA.md
   Сейчас это проверяемый приёмник webhook с сохранением событий.
   АВТОМАТИЧЕСКАЯ ВЫДАЧА PREMIUM НЕ РЕАЛИЗОВАНА.
   Требуется связывание подтверждённой покупки с конкретным аккаунтом,
   действительные webhook-секреты и проверка возвратов.

================= ВАЖНЫЕ ОГРАНИЧЕНИЯ =================

* Серверные модули не заменяют существующий app.py.
* Изменения фоновой загрузки, буферизации, перемешивания, UI и плеера
  относятся в основном к iOS/Android/Windows-клиентам и НЕ входят в этот
  серверный архив как новые маршруты.
* Для исправления старых веб- и Windows-клиентов можно вручную встроить
  from artist_metadata import normalize_response
  и перед return JSON каталога вызвать normalize_response(payload).
  Это действие НЕ выполняется автоматически, так как текущий код /api/tracks
  недоступен в репозитории.
* Если отсутствуют зависимости fastapi/httpx, устанавливай их только в
  текущую виртуальную среду действующего сервера, согласовав версии.
* Не публикуй служебную SQLite-базу каталога и секреты на GitHub.
* Проверка GET /api/artists?q=... и GET /api/daily-public-playlists требует
  действующей авторизованной сессии Nightwell.
* Если проверка сообщила, что у app.py нет identity(), нужен исходник
  действующего сервера для совместимого подключения. Установщик не
  будет придумывать схему авторизации.
