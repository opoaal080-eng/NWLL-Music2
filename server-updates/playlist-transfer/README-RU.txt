Nightwell Music · перенос плейлистов с обработкой на устройстве

Проблема старого импорта: сервер на каждый из 1000 треков мог выполнять до
нескольких поисковых запросов, сопоставлять кандидатов и многократно
записывать состояние в SQLite. Это нагружало основной сервер с музыкой.

Новый протокол:
  POST /api/imports/client
  {"provider":"yandex","name":"Название","mode":"balanced","items":[
    {"title":"Песня","artist":"Исполнитель","track_id":"VALID_ID",
     "found_title":"Песня","found_artist":"Исполнитель"},
    {"title":"Неизвестная","artist":"Исполнитель","track_id":null,
     "reason":"Не найдено в каталоге"}
  ]}

Разбор, дедупликация и сопоставление выполняются на iPhone/Android,
из локально полученной копии каталога Nightwell.
Сервер только проверяет вход, сохраняет готовый отчёт и по команде
POST /api/imports/{id}/commit создаёт плейлист и добавляет найденные ID.
Сохранение ограничено примерно 10 операциями в секунду.
GET /api/imports/{id} отдаёт items и причины для ненайденных треков.
Существующие эндпоинты списка, статуса, отмены и подтверждения сохраняются.

ВАЖНО: старый POST /api/imports возвращает HTTP 426 с просьбой обновить
приложение. Это намеренно, чтобы старые клиенты не перегружали ноутбук.
Система не ищет треки вне уже загруженного каталога. Ненайденные
показываются пользователю для повторной проверки и экспорта.

Установка:
1. Остановить Nightwell Music сервер.
2. В папке сервера с app.py и music_import_sources.py выполнить:
   .\\.venv\\Scripts\\python.exe путь\\к\\install_import_update.py --target .
3. Перезапустить сервер штатным батником.

Установщик создаёт резервную копию music_import.py в backups.
Новый IPA/APK требует серверного модуля с /api/imports/client.
История переносов и существующие плейлисты сохраняются.
Проверка: python -m unittest test_transfer.py


Поиск клипов YouTube (добавлено):
- Новая точка GET /api/music-videos/clip?title=...&artist=...
- Включается автоматически при установке music_import.py + music_videos.py.
- Нужен ключ YouTube Data API в переменной NW_YOUTUBE_API_KEY на сервере.
- Ключ нельзя вшивать в IPA/APK и нельзя публиковать на GitHub.
- На сервере жёсткий лимит 30 новых поисков за сутки, кэш 12 часов
  для найденных и 3 часа для ненайденных, по одному внешнему запросу.
- Если API не настроен, пункт «Клип» скрыт. Музыка не затрагивается.
- YouTube ролик открывается в официальном приложении или браузере,
  при нажатии клиент ставит музыку Nightwell на паузу.
- Видеофоны больше не используются: в плеере только анимированная обложка.
