# Nightwell Music: устройства и семейный Premium

Серверный модуль для существующего FastAPI-приложения Nightwell Music. Цена и оформление Premium остаются действующими: оплачивает владелец, а в его подписку можно пригласить ещё **2 отдельных аккаунта**. Всего в семье — **3 человека с владельцем**.

## Правила доступа

| Состояние аккаунта | Устройства | Premium |
| --- | ---: | --- |
| Free | 2 | Нет |
| Личный оплаченный Premium | 5 | По действующей личной подписке |
| Участник активной семьи | 5 на свой аккаунт | За счёт подписки владельца |
| Семья владельца истекла | 2, если нет собственного Premium | Семейные права приостановлены |

Лимит применяется к зарегистрированным устройствам **каждого аккаунта**, а не к трём людям суммарно. Это не обещание заданного числа одновременных потоков. Семья не объединяет избранное, историю, пароли, плейлисты или личные платежи.

- Только владелец с **прямым оплаченным Premium** создаёт приглашения. Полученный семейный доступ не позволяет пригласить ещё одну семью.
- Один аккаунт состоит максимум в одной семье, включая роль владельца. Свой активный платный период приглашённого не обнуляется.
- Для каждого приглашённого создаётся отдельная одноразовая ссылка на **7 дней**. Два действующих приглашения уже резервируют два места; лишнее приглашение нужно отозвать или дождаться истечения.
- Вступление происходит после входа, отдельным защищённым POST. Открытие ссылки само по себе не добавляет человека в семью.
- Если подписка владельца закончилась, состав семьи сохраняется, но семейные права прекращаются. После подтверждённого продления восстанавливаются. Собственный активный Premium участника продолжает действовать.
- Владелец может удалить участника, участник — выйти. Для удаления семьи есть отдельное действие. Эти действия не отменяют личные подписки.
- После понижения тарифа устройства не удаляются: активны первые два по стабильному порядку регистрации, остальные отмечены заблокированными. После Premium доступны до пяти снова.
- Ранее законно скачанные аудиофайлы не удаляются и не изменяются этим модулем. Права на новые скачивания по источникам проверяются существующим сервером.

## Граница интеграции

Полного действующего `app.py` в репозитории нет. Поэтому пакет не подменяет сервер и не угадывает имена cookie, хранилище сессий, структуру пользователей или устройство платёжного сервиса. Коммит и ZIP сами по себе ничего не устанавливают на production.

Нужен небольшой **адаптер именно к действующему серверу**. Установщик требует `--adapter` с `ADAPTER_CONFIGURED = True` и отказывает на отключённом шаблоне. Эта отметка подтверждает выполненную оператором настройку; статический `--check` не доказывает семантику авторизации и Premium.

`account_access_host.example.py` показывает контракт и намеренно отключён. В нём должны быть настроены:

1. `SESSION_KEY(request)` — стабильный идентификатор уже проверенной сервером сессии. Не `X-User-ID`, не `X-Session-ID` из запроса и не название устройства. Не используйте непроверенные клиентские значения как пользователя или сессию.
2. Прямая оплаченная подписка владельца. В примере исходный `premium_service.require` захватывается **до** любых изменений guards. Только его HTTP 402/403 означает Free. Сбои БД, сети и другие ошибки не превращаются в Free: проверка должна закрыться с ошибкой, а не выдавать ложные права или уменьшать лимит.
3. `BIND_EXISTING_PREMIUM(app, premium_service, controller)` — явное подключение семейных прав во все существующие проверки платных функций и в `/api/premium/me`. Автоматического proxy для неизвестных возвратов `.require()` нет.

Пример прямого источника подписки в шаблоне возвращает `expires_at=None`, если действующее время окончания ещё не подключено. Это неизвестный срок, а не выдуманная дата. Предпочтительно вернуть настоящий доверенный `expires_at` из личного платёжного состояния. При каждом запросе используется актуальное состояние подписки.

### Два обязательных изменения действующего приложения

В обработчиках платных возможностей используйте эффективный доступ, сохранив текущего пользователя для его музыки и данных:

```python
account_id = identity(request)  # фактический контракт существующей авторизации
app.state.nightwell_account_access.require_premium(str(account_id))
# Дальше работа с библиотекой ИМЕННО account_id, не владельца семьи.
```

Обработчик статуса подписки должен дополнить свой существующий ответ:

```python
original = existing_personal_premium_response(account_id)
return app.state.nightwell_account_access.premium_response(str(account_id), original)
```

Это **иллюстрации мест подключения**, а не готовые функции отсутствующего `app.py`. `premium_response` сохраняет личные платёжные поля и добавляет эффективный Premium/семейный источник. Счёт, оплата, возврат и управление автопродлением должны продолжать относиться к реальному личному плательщику; участнику нельзя выдавать управление счетами владельца семьи.

Если после аудита `.require()` используется только как отдельная проверка без нужного возвращаемого объекта, оператор может явно переназначить этот guard на `controller.require_premium`. Прямой оплаченный источник при этом обязан использовать заранее захваченный исходный метод, иначе семейный доступ может рекурсивно спонсировать другие семьи. Предпочтительны явные проверки через controller в конкретных обработчиках.

## Установка на копию сервера, затем на production

Нужен Python 3.10+ и существующий совместимый FastAPI. Используйте окружение действующего сервера; не обновляйте автоматически весь его стек. Модули работают рядом с `app.py`; данные доступа создаются отдельно в `account_access.sqlite3` при запуске приложения.

1. Подготовьте копию действующего сервера и настроенный адаптер, например `C:\Nightwell\account_access_host.py`. Не храните платёжные секреты и пароли в адаптере или репозитории.
2. На копии проверьте все основные сценарии из раздела «Проверка» ниже, включая реальный механизм авторизации и все Premium endpoints.
3. Перед заменой файлов остановите **только процесс Nightwell Music**, чтобы избежать загрузки смеси старых и новых модулей. Caddy, Chat и другие сервисы этим пакетом не изменяются. Не редактируйте `app.py` параллельно с установкой.
4. Выполните проверку без записи:

```powershell
py -3 install_account_access.py --check --target "C:\Nightwell\Server" --adapter "C:\Nightwell\account_access_host.py"
```

5. Если проверка прошла и адаптер проверен на копии, установите:

```powershell
py -3 install_account_access.py --target "C:\Nightwell\Server" --adapter "C:\Nightwell\account_access_host.py"
```

В Windows также доступны `Check_Account_Access.bat` и `Install_Account_Access.bat` с теми же двумя путями:

```powershell
.\Check_Account_Access.bat "C:\Nightwell\Server" "C:\Nightwell\account_access_host.py"
.\Install_Account_Access.bat "C:\Nightwell\Server" "C:\Nightwell\account_access_host.py"
```

Установщик проверяет синтаксис, наличие `app`, `identity`, `premium_service`, `premium_csrf` до запуска приложения, конфликты маршрутов и настроенный адаптер. Он не импортирует `app.py`, не открывает рабочую БД и не запускает сервер. Hook вставляется до `if __name__ == "__main__"`; повторный запуск не дублирует его. Если распознанный `uvicorn.run` или другой блокирующий запуск находится на верхнем уровне раньше hook, установщик отказывает: перенесите запуск в main guard или подключите модуль вручную.

Копируются четыре Python-модуля, `family_page.html`, настроенный `account_access_host.py` и изменяется только managed-блок `app.py`. Перед записью создаётся `backups/account-access-<дата>/manifest.json` с SHA-256 и исходными версиями затрагиваемых файлов. При сбое замены установщик пытается восстановить все уже затронутые файлы и сообщает путь резервной копии.

Запустите Music обычным способом и проверьте логи. Установщик ничего не перезапускает. Для новых пользователей предусмотрите клиентский сценарий регистрации устройства: строгий режим не разрешает прежний обход без секрета устройства.

### Если уже установлен старый account_devices

При marker `# Nightwell per-account device registry` или старом hook установщик останавливается. Не накладывайте два middleware и два набора `/api/devices` на одно приложение.

На копии сервера снимите резервные копии, отключите старый hook/маршруты, подготовьте клиентский переход на новые серверные секреты и проверьте новое ограничение. Старый идентификатор без секрета не доказывает владение устройством, поэтому автоматически переносить такие записи как подтверждённые нельзя. Старую БД не удаляйте и не заменяйте новым файлом. После согласованной ручной миграции повторите `--check`.

### Восстановление файлов

При остановленном Music укажите точную резервную копию из результата установки:

```powershell
py -3 install_account_access.py --target "C:\Nightwell\Server" --restore "C:\Nightwell\Server\backups\account-access-<дата>"
```

Проверяются привязка к каталогу и SHA-256 исходных файлов. Восстанавливаются только файлы данного обновления; новые файлы, которых раньше не было, удаляются. Команда может заменить более поздние ручные изменения этих файлов — сначала сохраните их отдельно. `account_access.sqlite3`, личные платежи, `.env`, основной каталог музыки и другие БД восстановлением файлов не затрагиваются. Сохраняйте новую БД доступа вместе с обычными резервными копиями; откат кода не является откатом её данных.

## Контракт клиента: устройства

Все private-запросы предъявляют **`X-NW-Device-Token`**, выданный сервером. Идентификатор и платформа без секрета больше не дают доступ. Сервер связывает регистрацию с доверенной сессией из адаптера, проверяет лимит атомарно и не полагается на локальный флаг Premium.

```http
POST /api/devices/register
Content-Type: application/json
X-CSRF-Token: <действующий токен защиты сессии>

{"platform":"ios","name":"Мой iPhone"}
```

Ответ содержит `ok`, `device_id`, `device_token`, `limit`. Нативный клиент сохраняет секрет в Keychain / защищённом хранилище и отправляет его при следующих запросах. `device_id` и `device_token` можно передать при повторной привязке ранее подтверждённого устройства к новой авторизованной сессии. Существующий ID в новой сессии без правильного секрета отклоняется.

В браузере API устанавливает cookie **`nw_device_token`** с HttpOnly, Secure и SameSite=Lax; JavaScript не должен извлекать этот секрет. Страница `/family` использует текущую авторизацию и CSRF.

- `GET /api/devices` — свои устройства, лимит, активные и заблокированные записи.
- `DELETE /api/devices/{device_id}` — удаление своего устройства и отзыв всех связанных с ним сессий в реестре доступа. Повторная регистрация из отозванной сессии не разрешается: нужен новый вход.
- `GET /api/account/access` — актуальный эффективный Premium, его источник и лимит устройств.

Реестр ограничивает логические устройства и сессии, но не является аппаратной аттестацией. Копию одного секрета нельзя надёжно отличить от того же устройства без дополнительных возможностей платформы. HTTPS, защищённое хранение и реальный отзыв серверных сессий остаются обязательной частью интеграции.

## Семья: страница и API

Откройте `https://music.nightwell.fun/family`. Владелец может создать приглашение и отправить отдельную ссылку каждому человеку. Секрет приглашения находится во fragment ссылки (`/family#invite=...`), поэтому не должен попадать в query string или серверные access-логи. Не публикуйте эти ссылки в общем доступе.

| Метод | Адрес | Действие |
| --- | --- | --- |
| GET | `/api/family` | Своя семья и роль |
| POST | `/api/family/invitations` | Создать приглашение владельцем |
| POST | `/api/family/invitations/preview` | Проверить приглашение; `token` в JSON, без вступления |
| POST | `/api/family/invitations/accept` | Принять приглашение текущим аккаунтом; `token` в JSON |
| DELETE | `/api/family/invitations/{id}` | Отозвать своё приглашение |
| DELETE | `/api/family/members/{account_id}` | Удалить участника владельцем |
| POST | `/api/family/leave` | Выйти из семьи участником |
| DELETE | `/api/family` | Распустить семью владельцем |

Изменения требуют входа и CSRF. Preview не меняет данные и может быть доступен без входа, с минимальным ответом без идентификатора владельца. Пользователь для принятия всегда берётся из текущей серверной авторизации, а не из `account_id` в теле запроса. В БД хранятся хеши секретов приглашений; одна ссылка не должна вступить двумя разными аккаунтами даже при одновременных запросах.

## Проверка перед рабочим включением

Автотесты пакета работают только с временными БД и fixture-приложениями. Их можно запустить отдельно от production:

```powershell
py -3 -m unittest discover -s . -p "test_*.py" -v
```

Для тестов HTTP нужен `httpx`, для модуля — существующий FastAPI; используйте тестовое окружение пакета. Дополнительно на копии **реального** сервера проверить:

- третий Free-девайс и шестой Premium-девайс отклоняются; удаление освобождает слот;
- нельзя обойти лимит отсутствием/изменением платформы или ID, а чужой token не подходит;
- отозванная сессия не регистрируется повторно без нового входа;
- владелец + два участника работают, третий участник/приглашение не проходят;
- истёкшая/отозванная/повторно использованная чужим аккаунтом ссылка не принимается;
- одновременно созданные приглашения/вступления не превышают вместимость;
- истечение или возврат личной подписки владельца отнимает семейные права на следующей проверке; продление возвращает их;
- свой оплаченный период участника и его личные данные сохранены;
- **каждый** старый платный endpoint использует эффективный guard, а `/api/premium/me` показывает его корректно;
- checkout, цены, автопродление и Lava продолжают действовать от имени личного плательщика;
- после понижения тарифа файлы не удалены, лишние устройства заблокированы, два доступных остаются предсказуемыми;
- подлинные CSRF и stable session_key корректны на web, iOS, Android и Windows.

## Охват маршрутов и WebSocket

HTTP middleware по умолчанию проверяет авторизованные запросы под `/api/`, `/stream/`, `/audio/`, `/media/`. Управление устройствами и семьёй, получение профиля / статуса подписки и заданные маршруты оплаты доступны для восстановления доступа, но также проверяют отзыв сессии; изменения дополнительно защищены CSRF. Публичная страница `/family` не раскрывает личные данные без API-авторизации.

Адаптер обязан проверить **все фактические приватные пути** действующего сервера. Если, например, загрузки доступны через `/download/`, передайте `protected_prefixes=("/api/", "/stream/", "/audio/", "/media/", "/download/")` в `module_install(...)` либо вызовите `controller.authorize_device(account_id, verified_session_key, device_token)` явно в нужном обработчике. Пользователь и session key здесь уже проверены действующей системой авторизации; не извлекайте их из произвольных клиентских заголовков.

HTTP middleware не перехватывает WebSocket. Для приватного WebSocket такой явный guard нужен при подключении и перед защищёнными сообщениями, чтобы отзыв или изменение тарифа учитывались дальше. Уже переданный аудиопоток и внешние URL источника нельзя отозвать задним числом данным middleware. Это граница интеграции, а не аппаратная аттестация или DRM.

Маршруты модуля ставятся перед существующим SPA catch-all / корневым Mount, сохраняя взаимный порядок остальных маршрутов приложения.

Создание ссылок ограничено 30 приглашениями за 24 часа на семью, включая использованные и отозванные. Превышение возвращает HTTP 429. Это ограничение не меняет вместимость семьи: максимум владелец и два участника.
