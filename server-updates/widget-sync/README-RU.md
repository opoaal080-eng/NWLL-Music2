# Nightwell Music: серверная синхронизация iOS-виджетов

Это новый модуль для существующего FastAPI сервера. **Он не включится сам по себе от установки IPA.**
В репозитории нет полного рабочего `app.py`, поэтому нельзя подтвердить, что модуль уже установлен на сервере.

## Установка

Скопируй `widget_sync.py` и `install_widget_sync.py` в отдельную папку на сервере.
Выполни:

```powershell
python install_widget_sync.py --target "C:\Nightwell Music\nightwell-music" --check
python install_widget_sync.py --target "C:\Nightwell Music\nightwell-music"
```

Установщик проверит совместимость существующего `app.py`, добавит один хук,
создаст резервные копии исходных файлов и скопирует модуль.
Перезапусти действующий сервер обычным батником. Модуль создаёт
`widget_sync.sqlite3` рядом с `app.py`.

Требуется, чтобы существующий `app.py` объявлял FastAPI `app`,
`identity(request)` и `premium_csrf(request)`. В остальных случаях
установка остановится без изменений.

## Привязка

1. В Nightwell Music открой Профиль → Виджеты и нажми «Создать код».
2. На iPhone зажми виджет «Сейчас играет», выбери «Изменить виджет».
3. Вставь код в поле «Код привязки» в течение 10 минут.
4. Виджет один раз обменивает код на собственный случайный токен,
   хранит его в Keychain расширения и получает только название,
   исполнителя, паузу/воспроизведение и JPEG-обложку.
5. В Профиль → Виджеты можно отозвать все выданные токены.

Для этой синхронизации **App Group не нужен**. Служба не даёт виджету
доступ к данным аккаунта или управлению воспроизведением.
WidgetKit самостоятельно выбирает, когда обновлять данные. Обычно
это не мгновенно и не каждую секунду.

## Безопасность

- Код одноразовый, случайный (64 бита), действует 10 минут.
- Выданный токен имеет 256 бит случайности, в SQLite хранится только SHA-256.
- Токен передаётся в заголовке Authorization по HTTPS, не в URL.
- Сведения об аккаунте, cookies, CSRF и устройствах не передаются виджету.
- Обложки до 220 КБ; чувствительные заголовки ответа содержат no-store.
- Создание кода, запись состояния и отзыв токенов требуют авторизации и CSRF.

## Исправление BAT-файлов для Windows

Скачай свежий архив и распакуй его полностью. BAT-файлы используют CRLF и ASCII. При отсутствии стандартной папки установщик попросит указать каталог с работающим `app.py`. Можно передать этот путь первым аргументом. Сначала `Check_Widget_Server.bat`, затем `Install_Widget_Server.bat`.


## V3 — новая привязка без AppIntent

Обнови установленный модуль через Install_Widget_Server.bat и перезапусти сервер. Существующая БД сохраняется. Удали старые виджеты, добавь новый «Сейчас играет». В нём появится одноразовый код (15 минут). Введи его в Профиль → Виджеты и нажми «Подключить». Виджет хранит свой собственный секрет внутри расширения и не требует поля настройки iOS. При необходимости нажми «Обновить данные виджета». Не публикуй коды и ключи.


## V3.1: исправление HTTP 401

Виджет использует заголовок `X-Nightwell-Widget-Token` вместо `Authorization: Bearer` при анонимной регистрации и чтении трека. Это предотвращает перехват случайного ключа проверкой JWT основного сервера. Поддержка старого Bearer остаётся. Установи свежий `widget_sync.py` через `Install_Widget_Server.bat` и перезапусти сервер. Проверочный маршрут: `GET /api/widgets/device/health` должен вернуть `{"widget_sync":"v3.1","ready":true}`. Если он возвращает HTTP 401, значит общая авторизация или прокси блокирует весь URL ещё до маршрута, и понадобится безопасное исключение именно для маршрутов `/api/widgets/device/register`, `/api/widgets/device/health`, `GET /api/widgets/state`, `GET /api/widgets/cover`; защищённые POST маршруты не освобождать. Не отправляй пользователям ключи или токены из логов.


## V3.2: исправление глобального HTTP 401

Серверный модуль теперь устанавливает узкий изолированный ASGI-маршрутизатор для публичной проверки `GET /api/widgets/device/health`, анонимной регистрации `POST /api/widgets/device/register`, и чтения `GET /api/widgets/state`, `GET /api/widgets/cover`. Эти операции проходят до проверки входа в основной аккаунт, но чтение музыки по-прежнему **требует отдельный секретный ключ виджета**. Привязка `POST /api/widgets/device/claim`, запись состояния, отзыв прав и другие API полностью сохраняют авторизацию аккаунта и CSRF. Такой подход не требует редактировать основной `app.py` вручную.

Установи модуль обновлённым `Install_Widget_Server.bat` поверх V3.1, перезапусти сервер и открой `https://music.nightwell.fun/api/widgets/device/health`. Ответ должен быть `{"widget_sync":"v3.2","ready":true}`, а HTTP-ответ содержать заголовок `X-Nightwell-Widget-Gateway: v3.2`. Если **на публичном домене** всё равно 401 или нет этого заголовка, вероятнее всего блокировка на внешнем прокси либо запрос попал на старый процесс сервера. Нужно проверить правила доступа прокси и запущенную версию, а не выдавать новые токены. Старая IPA V3.1 совместима с этим обновлением.
