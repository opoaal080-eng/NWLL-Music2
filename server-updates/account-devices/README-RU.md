# Nightwell Music: устройства аккаунта

## Лимиты

- Без подписки: **2 устройства**.
- С действующим Nightwell Premium: **5 устройств**.
- Через профиль можно увидеть привязанные устройства, время последней активности и удалить любое устройство.
- Когда Premium закончится, дополнительные устройства не удаляются, но блокируются до восстановления подписки или освобождения мест.

## Установка на настоящий сервер

В репозитории находятся `account_devices.py` и установщик `install_account_devices.py`. Основной серверный файл `app.py` в репозитории отсутствует. Совместимость сверена по копии от 12 ноября 2026 года, но действующий сервер может отличаться.

Установщик требует существующие `app`, `identity(request)`, `premium_service.require(account_id)` и `premium_csrf(request)`. Проверка подписки и CSRF выполняется через эти серверные функции, без внутренних HTTP-запросов.

Сначала на сервере проверь актуальную совместимость:

```powershell
python install_account_devices.py --check --target "C:\Nightwell\Server"
```

Если проверка прошла, установи модуль и перезапусти сервер:

```powershell
python install_account_devices.py --target "C:\Nightwell\Server"
```

Подставь настоящий путь к `app.py`. Установщик создаёт резервную копию и размещает `account_devices.sqlite3` рядом с приложением. **Коммит в GitHub не устанавливает модуль на работающий сервер.**

## API

- `POST /api/devices/register` — регистрирует устройство текущей сессии с `device_id`, `platform`, `name`.
- `GET /api/devices` — возвращает `devices`, `count`, `limit`, `premium`.
- `DELETE /api/devices/{device_id}` — отвязывает устройство, принадлежащее текущему аккаунту.

Запись защищена CSRF-токеном сессии. ID пользователя берётся из существующего сервера, а не из тела запроса. Превышение лимита отдаёт HTTP 409 и код `device_limit`.

## Переходный режим

Обновлённые нативные клиенты предъявляют `X-NW-Device-ID` и `X-NW-Device-Platform`. Старые клиенты и веб без заголовков временно допускаются, чтобы сразу не заблокировать пользователей. Поэтому **ограничение пока нельзя считать устойчивым к обходу**. Заголовок устройства — не криптографическая аттестация физического телефона или компьютера.

После удаления текущего устройства его сессия остаётся в старой системе авторизации, но запросы нативного клиента будут блокироваться до повторной регистрации устройства.
