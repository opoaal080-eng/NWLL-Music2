# Nightwell Music: привязка устройств к аккаунту

Готовый модуль для действующего FastAPI-сервера, без замены основного \`app.py\`.

## Возможности

- Без активной подписки: **2 устройства** на один аккаунт.
- С активной подпиской Nightwell Premium: **5 устройств**.
- У каждого устройства случайный или псевдонимизированный постоянный ID, платформа, имя и дата активности.
- В профиле можно увидеть свои устройства и **отвязать любое из них**.
- При достижении лимита сервер отвечает кодом HTTP 409 и \`code: device_limit\`.
- При истечении Premium устройства сверх бесплатного лимита становятся недоступными. Они не удаляются автоматически. В профиле остаётся возможность удалить старые.

## Установка

Нужны действующие маршруты \`/api/me\` и \`/api/premium/me\`, а также функция \`identity(request)\`, возвращающая ID пользователя. Права и сессии берутся из текущего сервера. Требуется библиотека \`httpx\`.

На серверном компьютере, в папке \`server-updates/account-devices\`:

\`\`\`powershell
python install_account_devices.py --check --target "C:\Nightwell\Server"
python install_account_devices.py --target "C:\Nightwell\Server"
\`\`\`

Затем перезапусти сервер Nightwell Music. Установщик сохранит резервную копию исходного \`app.py\`. Данные реестра хранятся в \`account_devices.sqlite3\` рядом с \`app.py\`.

**Основной сервер не изменится от одного коммита в GitHub.** Установку необходимо выполнить на машине, где запущен FastAPI.

## API

- \`POST /api/devices/register\` с JSON \`{"device_id":"ios_...","platform":"ios","name":"iPhone"}\`.
- \`GET /api/devices\` возвращает \`devices\`, \`count\`, \`limit\`, \`premium\`.
- \`DELETE /api/devices/{device_id}\` удаляет устройство **только из текущего аккаунта**.

Для операций записи требуется действующий \`X-CSRF-Token\` текущей сессии. Подлинность владельца определяется серверной авторизацией, переданный клиентом ID аккаунта не используется.

## Совместимость и защита

Обновлённые iOS/Android/Windows-клиенты передают \`X-NW-Device-ID\` и \`X-NW-Device-Platform\` для всех API-вызовов. Сервер отклоняет такие запросы, если устройство не зарегистрировано или лишилось доступа при смене тарифа.

На первом этапе старые приложения и веб-клиент без этих заголовков продолжают работать, чтобы обновление сервера не заблокировало пользователей. Поэтому **пока не обновлены все клиенты и не введено обязательное предъявление устройства для всех авторизованных запросов, ограничение нельзя считать полностью защищённым от обхода**. Идентификатор установки не равен аппаратному серийному номеру и не является криптографическим подтверждением физического устройства.

Информация о конкретных устройствах не выдаётся другим аккаунтам. При удалении текущего устройства его сессия остаётся в старой системе авторизации, но новые защищённые запросы будут отклонены, пока оно не зарегистрируется снова.
